# 工作流补全与稳定性加固计划

**目标：** 让已选商家贯穿全站；失败或卡住的检测可以安全恢复；交付报告能明确判断是否满足“3题实测且至少首批推荐一次”的验收要求。

**实现原则：** 保留历史检测，不覆盖失败记录；手机实测仍固定为3个独立对话；不新增数据库迁移或外部 API 调用；辅助证据不冒充豆包官方排名依据。

## 1. 全局商家上下文

- [x] 使用同源 Cookie 保存当前商家。
- [x] 业务页缺少 `merchant` 参数时自动补回，保留其他筛选参数。
- [x] 商家切换器同步更新 Cookie。
- [x] 增加路由与导航测试。

## 2. 检测失败恢复

- [x] 仅允许失败或部分完成的检测创建重试记录。
- [x] 新记录复用商家、题库和适配器，保留原失败记录。
- [x] Worker 启动时将超时的运行中任务标记为失败并给出原因。
- [x] 增加后端路由和 Worker 测试。

## 3. 前端重试入口

- [x] 检测列表展示错误摘要。
- [x] 失败或部分完成记录提供“重新执行”操作。
- [x] 重试后跳转到新检测详情。
- [x] 增加页面测试。

## 4. 交付验收清单

- [x] 核心标准：3道答案均确认，且至少1道进入首批推荐。
- [x] 商家资料、题库、平台查缺、同题复测作为辅助证据单独展示。
- [x] 未满足核心标准时禁用打印交付报告并解释原因。
- [x] 增加纯函数和页面测试。

## 5. 启动与运行稳定性

- [x] 同时核验 API、Web 和 Worker 心跳。
