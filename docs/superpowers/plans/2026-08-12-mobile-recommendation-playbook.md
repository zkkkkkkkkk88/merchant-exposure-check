# 手机版豆包推荐率提升方案实施计划

**目标：** 把已完成的三题手机实测转换成商家看得懂、可核验、可执行并能复测对比的提升方案。

**约束：** 不调用外部 AI；不把推断写成事实；最多展示 3 个竞品、每个 3 条原因、3 个行动；不同题库不做伪对比。

## 任务 1：后端证据诊断

- 新建 `services/api/app/mobile_checks/playbook.py`，实现纯规则诊断器。
- 从已确认轮次提取逐题提及结果、目标机构在答案中的序号、竞品及其答案原文证据。
- 对竞品理由标注“答案证据 / 来源已确认 / 待核实”，无证据时明确显示待核实。
- 先写失败测试，再实现，并限制展示数量。

## 任务 2：行动建议与复测对比

- 根据名称不一致、缺失场景、竞品证据差距、来源差距和补充推荐状态生成最多 3 个行动。
- 每个行动包含原因、步骤、所需材料、示例、完成标准和可信度。
- 只在验证题一致时生成上一轮与本轮的指标、逐题变化；否则返回空对比。
- 增加“不虚构商家医保、设备、资历”等回归测试。

## 任务 3：接口与前端契约

- 扩展 `MobileWorkspaceRead` 和前端 `MobileWorkspaceData`，加入 `recommendationPlaybook`。
- 在 workspace 服务中加载上一轮可比数据并返回提升方案。
- 保持无确认轮次时的兼容空状态。

## 任务 4：手机版实测页面呈现

- 新建“推荐率提升方案”组件，依次展示诊断、竞品证据、优先行动和复测变化。
- 放在来源差距之后，使用卡片和短列表，避免再次出现宽矩阵与信息爆炸。
- 补充前端测试，验证当前 1/3 补充提及、缺失问题、证据标签及行动文案。

## 任务 5：验证

- 运行一次后端 mobile checks 相关测试。
- 运行一次前端 mobile checks 相关测试与构建。
- 用当前真实轮次接口检查方案结构和页面可读性。
