# 手机实测公开来源自动查找设计

## 目标

把“独立来源审计结果”从必填式手工粘贴改为项目自动查找、用户核对确认。系统只收集能够提供真实公开网址的来源，不把“本次未找到”解释为“商家没有发布”。

## 检索范围

- 每轮固定包含目标商家。
- 竞品仅包含在3份答案中至少出现2次的机构。
- 目标商家与竞品合计最多4家。
- 每家最多保留3条来源。
- 每家最多执行1次综合公开搜索，因此每轮最多4次外部搜索调用。

## 方案

采用混合自动查找：优先复用该目标商家最近一次“平台查缺”中已有真实网址的结果；其余机构使用现有联网搜索适配器各执行一次综合检索。暂不为每个机构逐平台调用地图、工商、招聘等接口，避免一次操作产生数十次调用。

综合检索按以下优先级寻找来源：

1. 政府、工商或行业登记页面。
2. 高德、腾讯等地图详情页。
3. 机构官网或可公开访问的官方主页。
4. 招聘、媒体或其他可信第三方页面。

没有真实网址的搜索结论不进入候选来源。

## 后端组件

新增手机实测来源发现接口，接收：

- 目标商家 ID。
- 本轮位置文本。
- 自动解析得到的竞品及其出现次数。

后端负责重新执行范围限制，不能依赖前端自行保证调用上限。返回值按机构分组，每条候选来源包含：

- 机构名称。
- 来源类型。
- 页面标题。
- 可核验事实摘要。
- 真实网址。
- 证据属性（官方、第三方或商家自述）。
- 是否复用自平台查缺。

来源按规范化网址去重，并对机构名称进行现有别名规则匹配。

## 前端交互

用户完成3份回答粘贴并点击“识别答案”后，页面显示“自动查找公开来源”按钮。

查找完成后：

- 按机构分组展示候选来源卡片。
- 每条显示来源类型、标题、事实摘要和可点击网址。
- 候选项默认处于待核验状态，用户勾选后才作为已确认来源保存。
- 用户可以取消不相关或名称匹配错误的结果。
- 已确认候选来源在提交本轮时转换为现有 `MobileSourceCreate` 数据结构，无需数据库迁移。

原来的大文本框改为折叠的“手工补充来源”，继续支持既有分隔格式，用于补充自动搜索遗漏的页面。

## 状态与错误处理

- 查找期间按钮显示执行中并禁止重复提交。
- 本轮已有结果时不自动重复调用；用户必须主动点击“重新查找”。
- 单个机构搜索失败不影响其他机构结果。
- 没有结果时显示“本次未找到可核验来源”，并明确说明不代表商家没有发布。
- 未配置联网搜索服务时保留手工补充入口，并给出配置提示。
- 返回结果缺少网址、网址格式无效或机构范围超限时由后端丢弃。

## 数据流

1. 前端解析3份回答，统计竞品出现次数。
2. 前端提交目标商家、位置和重复竞品候选。
3. 后端验证商家、裁剪机构范围并复用已有平台证据。
4. 后端对仍缺来源的机构逐家执行一次综合公开搜索。
5. 后端规范化、去重并返回最多3条候选来源。
6. 用户勾选确认，前端把自动结果与手工补充结果一起提交现有手机实测保存接口。
7. 来源差距表和行动建议继续读取已确认来源，不改变现有计算口径。

## 测试要求

- 单元测试竞品至少出现2次、最多3个竞品的筛选规则。
- 后端测试目标商家始终包含、总机构数不超过4、每家来源不超过3。
- 后端测试无网址结果被过滤、重复网址被合并、部分搜索失败仍返回其他结果。
- 前端测试按钮仅在答案识别后出现、加载状态、候选勾选和手工补充入口。
- 保存流程测试自动确认来源能够进入现有来源差距计算。

## 不在本次范围

- 不直接读取豆包内部“21篇资料”列表。
- 不自动登录商家账号或代替商家发布内容。
- 不保证豆包一定抓取某个公开页面。
- 不新增数据库表或迁移。
