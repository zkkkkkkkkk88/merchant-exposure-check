# 手机实测分阶段工作台设计

## 目标

重新组织手机实测页面的信息层级，让商家按“测试—核对—理解—改进”的顺序完成任务，减少重复卡片、空状态和超长页面造成的混乱。本次不改变三道题、集中粘贴、结果解析或提升建议的业务规则。

## 页面层级

采用“分阶段工作台”布局：

1. 页面标题与商家切换。
2. 上一轮指标区，明确标注数据所属轮次和核实时间；没有有效结果时显示“暂无已确认结果”，不使用四个 0% 冒充成绩。
3. 当前任务区，以步骤条显示：选择 3 题、录入回答、核对结果、查看提升建议。
4. 上一轮实测记录，合并上一轮状态、三道问题、完整回答和确认结果，默认折叠。
5. 推荐率提升方案，作为完成实测后的主要输出，提前到来源空状态之前。
6. 证据与平台查缺，将原“来源差距”并入该区域；没有来源时只显示一行提示和查缺入口。
7. 历史对比放在页面底部，仅在存在可比轮次时显示。

## 当前任务区

- 未创建验证集时，突出“从候选题库选择 3 题”。
- 已选择题目但未录入时，显示三道题、一键复制和“开始录入回答”。
- 录入阶段只展示集中粘贴、识别与核对所需控件，其他结果区保持折叠或移到其后。
- 保存完成后，当前任务区显示完成状态和“开始新一轮”；旧题及旧回答进入上一轮记录，不重复平铺。
- “更换本轮 3 题”作为次要操作，放在题目区右上角或更多操作中，不与主按钮争抢权重。

## 指标规范

- 指标标题标明“上一轮结果”，并显示轮次完成时间。
- 没有已确认轮次时显示一个紧凑空状态，不渲染提及率、首批推荐率、场景覆盖率和信息准确率的 0%。
- 指标有数据时保持四项，但统一卡片高度、数字对齐和说明文字。
- 指标和上一轮记录必须来自同一轮次，避免题目已更换而指标仍指向旧题造成混淆。

## 结果与建议

- 上一轮记录默认折叠；展开后按 Q1–Q3 显示问题、完整回答、提及状态和排名。
- 提升方案统一使用：问题原因、缺失信息、优先发布渠道、准备材料、执行步骤、完成标准。
- 详细证据和长回答使用折叠结构；展开时保留自然换行，避免横向滚动。
- 来源差距有数据时显示紧凑对比表；没有数据时不占用完整大卡片。
- 平台查缺功能完成后，相关建议直接链接到对应平台异常详情。

## 视觉与响应式规范

- 卡片使用统一圆角、边框、内边距和标题结构；同层内容只使用一种标题尺寸。
- 主操作使用实色按钮，每个步骤最多一个主按钮；次要操作使用描边或文字按钮。
- 桌面端保持单列阅读流，不采用复杂双栏；最大内容宽度与现有页面一致。
- 窄屏下指标改为两列，步骤条可换行，题目与操作垂直排列，按钮保持可点击宽度。
- 色彩只表达状态和主操作，不能依赖颜色单独传达结果；状态同时显示文字。

## 可访问性与验证

- 步骤使用有序结构并标明当前步骤；折叠使用原生 `details/summary` 或等价可键盘操作控件。
- 每个按钮有明确文字，焦点状态可见，表单标签与控件关联。
- 前端测试覆盖无指标空状态、各步骤状态、上一轮折叠、建议排序和来源空状态。
- 实际页面验证桌面、平板和手机宽度，并检查长回答、长问题及多项建议的布局。
