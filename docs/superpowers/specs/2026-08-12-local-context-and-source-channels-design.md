# 县级区域背景与来源渠道设计

## 目标

新商家首次建档或地址发生修改时，通过火山方舟联网检索一次区域背景并缓存。问题生成、地域行动和发布渠道建议读取缓存及真实检测来源，避免使用不存在的机场、车站、商圈或固定平台模板。

## 地域粒度

系统解析并保存省、市、县/区、乡镇/街道及可核验地标。用于问题生成的地域名称严格按以下顺序选择：

1. 已识别并确认的县、自治县或县级市；
2. 没有县级信息时使用地级市；
3. 没有市级信息时使用省；
4. 地域信息均不可确认时停止生成地域问题，提示商家补充地址。

商家填写了具体地址时，联网检索必须尝试精确到县。不得因为原“城市”字段填写了省名而忽略地址中的市县信息。澜沧商家的问题应使用“澜沧县”，页面背景可显示“普洱市 · 澜沧县”，不得只使用“云南”。

## 区域背景缓存

新增每商家一份区域背景记录，包含：

- 行政层级：省、市、县/区、乡镇/街道；
- 标准化地址；
- 已核验的附近地标、道路和片区；
- 可合理使用的交通方式；
- 明确不可确认的设施不进入建议；
- 检索来源 URL、更新时间和原始摘要。

首次保存完整商家资料后自动生成；地址、省市县字段变化后标记失效并重新生成。其他画像修改不重复调用。联网失败时保留用户填写的信息，不伪造区域轮廓，并允许稍后重试。

## 联网检索约束

火山方舟请求明确要求只返回有来源支持的行政层级、真实地标和交通信息。机场、火车站、商业中心等只有在回答引用来源且与门店地址存在明确关联时才能进入缓存。不能从县城规模或常识推测设施存在。

## 发布渠道

每次检测后汇总火山方舟回答的 citation 域名，并与行动缺口关联。行动页面将渠道分为：

1. `本次回答实际引用`：展示域名、引用次数和对应问题；
2. `商家可自主维护`：商家自有官网或确认可认领、编辑的门店平台；
3. `需要投稿或联系平台`：资讯、媒体和行业目录，不暗示商家可以直接编辑；
4. `仅作参照`：无法确认发布方式或不适合商家提交的信息源。

系统不根据域名名称自动断言平台可编辑。没有维护方式证据时默认归为“仅作参照”。固定的“官网、地图、团购平台”只作为缺少真实 citation 时的候选检查项，并明确标记“需确认是否已开通”。

## 数据流

1. 保存商家 → 判断地址相关字段是否变化；
2. 需要时创建区域背景任务，后台调用火山方舟联网检索并缓存；
3. 生成问题 → 使用县优先的最细确认地域；
4. 执行检测 → 保存原始 citation URL 与域名；
5. 生成行动 → 结合区域背景、当前商家资料、缺口问题和真实 citation；
6. 页面展示背景更新时间、渠道来源依据和无法确认项。

## 异常处理

- 区域背景处理中：商家可继续编辑资料，但地域问题生成按钮提示等待背景完成。
- 联网失败：展示失败原因和“重新识别区域”操作，不回退到虚构模板。
- citation 为空：明确写“本次回答未返回可追溯平台”，不声称应该去某个平台发布。
- 地址修改：旧背景保留为历史审计信息，但不再参与新问题或行动生成。

## 验证

- 县、市、省三级回退单元测试；县存在时必须优先使用县。
- 地址变化触发一次刷新、非地址画像变化不触发的测试。
- 没有来源时不生成机场、车站、商圈的测试。
- citation 域名进入行动渠道且未知可维护性默认“仅作参照”的测试。
- 真实页面验证澜沧商家使用“澜沧县”，并展示实际引用域名而非固定平台。
