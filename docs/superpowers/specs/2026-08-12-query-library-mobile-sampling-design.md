# 问题题库与手机实测抽样分离设计

## 目标

将“问题策略”“完整检测”“手机实测”明确拆分：问题策略维护 10–20 道候选题，完整检测使用用户已启用的问题，手机实测只选择其中 3 道以控制人工时间成本。

## 模块职责

### 问题策略

- 每次为商家生成 15 道候选题，允许用户审核、启用、停用和修改。
- 口腔医疗商家的推荐题限定为民营同类机构，覆盖地域、口碑、稳定经营、服务项目、医生、设备、价格、首次就诊等场景。
- 餐饮等其他行业继续使用各自行业规则，不出现“民营/公立”条件。
- 问题策略不因手机实测只用 3 题而缩减题库。

### 完整检测

- 使用当前题库中所有“已审核且已启用”的问题。
- 用户在问题策略中停用的问题不进入新检测。
- 历史检测保留当时题目和结果，不受后续题库修改影响。

### 手机实测

- 每轮固定使用 3 道题，目的是减少人工打开豆包独立对话的次数。
- 默认从已审核且启用的推荐题中，按不同场景自动选出 3 道代表题。
- 页面提供“更换本轮3题”，用户可从候选题库中重新勾选，必须且只能选择 3 道。
- 更换手机实测题只创建新的手机验证集，不修改、不删除问题策略题库。
- 手机实测不使用品牌核验等非推荐题作为默认抽样题。

## 数据与交互

- 问题策略页面继续显示完整候选题库及审核、启用状态。
- 手机实测页面显示当前 3 题，并提供题目选择器：列出当前题库中已审核、已启用、推荐意图的问题。
- 保存选择后，新验证集成为后续手机实测默认题集；已完成轮次仍指向原验证集。
- 若可选推荐题不足 3 道，提示用户先回到问题策略审核并启用至少 3 道题。

## 复测与比较

- 只有两轮的规范化题目完全一致时，才展示提及率、首批推荐率和逐题变化。
- 选择了不同的 3 题时，不直接比较百分比，并提示“题目已变化，请使用相同题目完成下一轮后再比较”。
- 完整检测与手机实测属于不同检测口径，两者指标不互相覆盖。

## 当前商家处理

- 澜沧皓雅口腔门诊部的问题策略扩展为 15 道民营口腔候选题。
- 当前 3 道民营口腔题保留为默认手机验证集。
- O’eat Gastronomy 保持餐饮候选题和现有 3 道手机抽样题，不增加医疗行业字段或提示。

## 验收标准

- 皓雅的问题策略页面可看到 15 道候选题，手机实测仍只显示 3 道。
- 用户能从至少 3 道已审核启用的推荐题中更换本轮 3 题。
- 更换后完整题库数量和题目状态不变，历史手机轮次不变。
- O’eat 页面没有“民营、公立”等医疗限定。
- 同题复测可比较，异题复测不产生误导性百分比变化。
