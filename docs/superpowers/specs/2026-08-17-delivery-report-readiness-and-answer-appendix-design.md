# 交付报告验收与原始回答附录设计

## 目标

1. 将“报告是否可交付”和“商家是否获得首批推荐”分开，避免用不可控的排名结果阻塞交付。
2. 压缩报告正文中的原始回答，让用户优先看到结果、同行分析和行动建议。
3. 网页保留完整核验材料，PDF 默认输出适合阅读和交付的摘要版本。

## 交付验收规则

- 唯一阻塞条件为本轮未完成 3 个独立对话的确认。
- 3/3 道回答确认后，报告标记为“核心检测已完成”，允许打印或另存为 PDF。
- “目标商家至少获得 1 次首批推荐”保留在验收清单中，但改为非阻塞的进阶目标。
- 未获得首批推荐时显示：“首批推荐属于进阶成果，不影响本次检测报告交付。”
- 商家资料、问题审核、公开平台查缺和同题复测继续作为辅助完成项展示，不新增阻塞条件。

## 可见性分级

报告根据本轮 3 道已确认回答显示一个可见性等级：

- 0 道提及：尚未建立可见性。
- 1 道提及：初步可见。
- 2 道或 3 道提及：稳定可见。
- 在满足上述任一提及数量的同时，至少 1 道为首批推荐：强势可见。

首批推荐优先级最高。例如 1/3 道提及且该题为首批推荐时，等级为“强势可见”。没有完整 3 道确认结果时不计算等级，显示“等待完整实测”。

## 报告正文

- 顶部结论卡将“至少首批推荐一次：是/否”改为“可见性等级”。
- 继续展示“目标商家被提及”“首批推荐”和“六步证据进度”三个量化结果。
- 第 02 节标题改为“3 个独立对话结果摘要”。
- 每道题只展示问题文本、提及标签和目标商家位次；没有位次时不显示位次文案。
- 正文不展示回答正文或截断片段。

## 网页原始回答附录

- 在第 06 节之后、结论边界之前新增“原始回答附录”。
- 附录整体说明其只用于核验豆包原话，不属于报告摘要。
- 三道题各自使用原生 `details/summary` 折叠结构，默认关闭。
- 每个折叠标题显示题号、问题和提及结果；展开后展示完整原始回答。
- 原生控件必须可通过键盘聚焦、展开和收起，不添加只支持鼠标的自定义交互。

## PDF 输出

- 打印样式使用 `display: none` 隐藏整个原始回答附录。
- PDF 保留第 02 节的三题结果摘要。
- 打印按钮只在 3/3 道回答尚未确认时禁用，不再受首批推荐次数影响。

## 验证标准

- 3/3 道确认且 0 次首批推荐时，报告允许打印，并显示首批推荐为进阶目标。
- 当前商家 3/3 道均补充提及时，显示“稳定可见”。
- 0/3、1/3、2/3 和存在首批推荐四种情况均得到正确等级。
- 网页正文不出现完整回答，附录默认折叠且可逐题展开。
- 打印媒体样式隐藏原始回答附录，但保留三题结果摘要。
