# 手机版豆包三对话验证流程设计

## 目标

将现有最多 15 题、逐题录入和逐题确认的手机版豆包验证流程，缩减为 3 个独立新对话、一次集中粘贴、一次统一确认，同时修复历史题库混抽和商家误选问题。

## 验证流程

1. 用户必须先明确选择目标商家；未选择时页面只显示商家选择入口，不静默使用列表第一家。
2. 系统仅从该商家的最新版已审核题库生成验证集，不读取任何旧版本题目。
3. 验证集固定包含 3 个相互区分的推荐问题，优先覆盖：本地综合推荐、口碑或体验场景、核心服务或首次就诊场景。品牌事实核验不占用这 3 个推荐问题。
4. 页面提供“一键复制全部问题”，并明确提示用户在豆包中分别开启 3 个新对话，以免后续回答受前文影响。
5. 用户将 3 份回答集中粘贴到一个输入区。粘贴格式使用问题编号或明显分隔符；系统自动拆分回答并预识别目标商家是否出现、推荐层级、竞品和答案摘要。
6. 页面默认展示自动识别结果，只突出无法确定或互相矛盾的项目。用户可修正后一次性提交并确认整轮结果，不再逐题点击确认。
7. 来源差距使用独立的来源审计输入，不混入推荐率分母。来源内容粘贴一次后生成目标商家与竞品的明显对比表。

## 题库与历史数据

- 生成手机验证集时，后端先定位该商家版本号或创建时间最新的题库，再从其中选择已审核且启用的题目。
- 已创建但尚无检测轮次引用的旧手机验证集可直接删除并重建。
- 旧题库采用混合清理策略：未被联网扫描、人工检查、报告或手机验证记录引用的版本物理删除；存在历史引用的版本保留但标记归档，并从普通列表和所有新任务中隐藏。
- 清理操作不得级联删除任何已完成扫描、分析、报告或已确认手机检测记录。
- 当前商家地区以最新版资料中的“澜沧拉祜族自治县”为准；“普洱沧县”“云南 1-888”等旧错误题目不得进入新验证集。

## 页面行为

- 商家切换应保留当前页面路径，并更新 `merchant` 查询参数。
- 页面显示当前商家名称、地区、题库版本和 3 题数量，便于用户开始前核对对象。
- 若最新版题库不足 3 个合格推荐问题，页面提示返回题库补充或审核，不得从旧版补齐。
- 自动解析失败时保留原始粘贴文本，不丢失用户输入，并允许手动修正后统一确认。

## 数据与接口

- 手机验证集继续保存题目快照关系，但新建集合最多且必须为 3 题。
- 新增批量回答解析接口或等价的服务层方法，返回每题的建议识别结果和置信状态；保存前仍由用户统一确认。
- 题库增加可查询的归档状态，普通题库列表默认排除归档版本；历史详情仍可通过既有记录访问。
- 旧题库清理以数据库引用检查为前置条件，并返回删除、归档、跳过的数量摘要。

## 验证标准

- 未指定商家访问 `/mobile-checks` 时不自动生成或展示其他商家的题目。
- 指定澜沧皓雅口腔门诊部后只显示 3 题，且不包含“普洱沧县”“云南 1-888”等旧文本。
- 新验证集的 3 个题目全部来自同一个最新题库版本。
- 三份回答可一次粘贴并生成 3 条预识别结果，用户一次操作即可确认整轮。
- 来源对比表继续明确展示目标商家与各竞品的来源有无、差距和缺口。
- 清理旧题库后，已有历史扫描和报告仍能正常打开。
