# 问题库与后台检测闭环设计

## 目标

让用户能够在问题库中筛选、编辑和审核真实问题，并用所有“已批准且已启用”的问题创建火山方舟后台检测任务。任务创建后立即返回，用户不需要停留或等待；任务状态和结果持续写入数据库，可随时从检测记录页查看。

## 范围

本次包含：

- 修复问题库分类筛选，并显示各分类的问题数量。
- 将问题文字、审核状态和启用状态持久化到现有 `PATCH /queries/{query_id}` 接口。
- 在问题库和检测记录流程中提供“开始后台检测”操作。
- 使用现有 `POST /scan-runs` 创建基于当前问题集的 `ark` 检测任务。
- 由独立 Worker 在后台处理排队任务。
- 检测详情页自动刷新运行状态，完成后提供报告入口。
- 为保存失败、创建失败和无可用问题提供明确提示。
- 隐藏尚未实现的失败问题重试按钮和无有效目标的报告入口。

本次不包含：

- 按次手工勾选问题。用户通过“启用”开关控制参与范围。
- 失败问题单独重试。
- 通知中心、短信、邮件或浏览器推送。
- 多 Worker 调度、任务取消和优先级队列。

## 核心规则

1. 一次检测使用同一问题集内所有 `review_status=approved` 且 `is_enabled=true` 的问题。
2. 点击“开始后台检测”只负责创建任务，不同步等待模型返回。
3. 独立 Worker 从数据库领取排队任务并逐条执行，关闭页面不影响任务。
4. 问题文字在输入框失去焦点时保存；审核、拒绝和启用操作点击后立即保存。
5. 保存期间显示“保存中”，成功显示“已保存”，失败显示错误并恢复操作前的数据。
6. 没有可检测问题时禁用开始按钮，并提示用户先批准和启用问题。
7. 同一商家允许保留多次检测记录；每次任务固定绑定创建时的问题集版本。

## 前端组件

### 问题库工作区

`QueryTable` 继续负责本地筛选和行级交互，但所有业务修改通过注入的 API 操作持久化。分类标签显示“全部 30”“地域 5”等数量；切换标签只改变当前表格可见行，不改数据库。

每行维护独立保存状态，避免一条问题保存时锁住整张表。修改失败时恢复该行先前值并显示可读错误。批量批准仅更新待审核问题，并等待所有更新成功后刷新可检测数量；部分失败时保留成功项并列出失败数量。

页面顶部显示“可用于检测 N 条”和“开始后台检测”按钮。按钮使用最新问题集 ID 创建 `adapter_name=ark` 的任务，成功后立即跳转到 `/scans/{scanId}`。

### 检测详情

运行中详情采用客户端轮询容器，每 2 秒请求一次任务详情。状态进入 `completed`、`partial` 或 `failed` 后停止轮询。页面展示成功数、失败数和已处理总数；完成或部分完成时显示报告入口。

轮询网络失败不会改变任务状态，页面显示“暂时无法刷新，正在重试”。用户可以离开页面，Worker 继续运行。

### 检测记录

记录页继续从 API 读取真实任务。排队中和运行中的记录可进入详情页；已完成和部分完成的记录同时提供报告入口。不存在实现的操作不渲染可点击按钮。

## 后端与运行方式

现有查询更新、任务创建和 Worker 数据模型满足本次需求，不新增数据库表。必要时只补充读取顺序或响应字段，不改变已存数据。

项目运行需要三个进程：

- FastAPI API：接收保存、创建和查询请求。
- Scan Worker：持续领取 `queued` 任务并写入结果。
- Next.js 前端：提供交互界面并轮询状态。

Worker 与 API 共用 `merchant-exposure.db` 和同一套方舟环境变量。启动文档必须明确三个进程缺一不可。

## 错误处理

- 查询更新返回 404：提示问题已不存在，并建议刷新页面。
- 查询更新返回其他错误：恢复旧值并允许用户再次操作。
- 创建任务返回 409：提示当前没有已批准且启用的问题。
- 创建任务网络失败：保留当前页面和问题状态，允许重新点击。
- Worker 单条调用失败：记录失败结果并继续剩余问题，最终状态为部分完成或失败。
- 详情轮询失败：不清除已有进度，不把网络错误误报为检测失败。

## 测试与验收

前端自动化测试覆盖：

- 点击分类后只显示该分类的 5 条真实数据映射。
- 修改文字失焦后调用更新接口，并显示保存结果。
- 审核、拒绝、启用操作写入接口；失败时恢复原值。
- 没有可用问题时开始按钮禁用。
- 创建任务成功后跳转对应详情页。
- 运行中详情会继续轮询，终态停止轮询并显示报告入口。

后端自动化测试继续覆盖任务只能包含已批准且启用的问题，以及 Worker 的成功、部分失败和持久化行为。

人工验收流程：选择商家，切换六个分类，批准并启用问题，创建后台检测，立即离开详情页，再从检测记录返回并看到任务持续推进，最终打开真实报告。刷新问题库后所有修改仍然存在。
