# 免域名云端测试部署设计

## 目标

把当前 Next.js、FastAPI、后台 worker 和 PostgreSQL 项目部署到已购买的腾讯云 Ubuntu 24.04 轻量服务器。部署完成后，本地电脑可以关机，受邀测试者通过一个 Cloudflare 临时 HTTPS 地址访问，并使用同一组共享用户名和密码。

本阶段面向少量受信任测试者，不建设正式用户系统，不购买域名，也不承诺固定网址或生产级可用性。

## 约束与选择

- 服务器为中国香港 2 核 2 GB、40 GB SSD 的 Ubuntu 24.04 实例。
- 服务器已安装 Docker、Docker Compose 和 Git，并已有约 2 GB Swap。
- 访问入口使用 Cloudflare Quick Tunnel。它提供随机 `trycloudflare.com` HTTPS 地址，不要求域名，但隧道进程重建后地址可能改变。
- 使用入口层 HTTP Basic Auth 作为共享密码保护。所有浏览器请求先经过 HTTPS 隧道，再通过认证入口进入应用。
- PostgreSQL、FastAPI、worker 和 Next.js 均只加入 Docker 内部网络，不直接暴露公网端口。
- 豆包等真实 API 密钥只保存在服务器的生产环境文件中，不进入镜像、Git 或浏览器代码。

## 架构

生产 Compose 包含六个服务：

1. `db`：PostgreSQL，使用命名卷保存数据，仅接受内部网络访问。
2. `api`：FastAPI，以非 reload 模式监听容器内 `8000` 端口，启动前执行数据库迁移。
3. `worker`：运行现有扫描 worker，与 API 共用数据库和服务端密钥。
4. `web`：构建并运行 Next.js 生产版本，监听容器内 `3000` 端口。
5. `gateway`：Caddy 入口。先校验共享密码，再把页面请求转发给 `web`，把 `/api/*` 去掉 `/api` 前缀后转发给 `api`。
6. `tunnel`：Cloudflare Quick Tunnel，只建立出站连接，将随机 HTTPS 地址转发到 `gateway`。

浏览器不会直接访问 API 容器。浏览器端状态请求使用同源 `/api`；Next.js 服务端请求使用内部地址 `http://api:8000`。这样无需把 API 公网暴露，也避免把服务器内部地址写进前端包。

## 认证与安全

- Caddy 对页面和 `/api` 使用同一套 Basic Auth，避免绕过页面直接调用接口。
- 密码只以哈希形式提供给 Caddy。部署时在服务器交互式生成哈希，用户无需把明文密码发给 Codex。
- Compose 不映射数据库、API、worker 或前端端口到公网；服务器防火墙不开放 `3000`、`8000` 或 `5432`。
- Quick Tunnel 提供浏览器到 Cloudflare 的 HTTPS。该方案只用于测试；若转为长期或商业使用，应更换为自有域名、固定 HTTPS 地址和独立用户账号。
- 共享密码不能区分操作者，也不能提供按用户的数据隔离或审计。知道密码的人拥有同等应用访问能力。

## 配置与秘密

仓库提供不含秘密的生产环境示例，服务器保存实际生产环境文件，至少包括：

- PostgreSQL 数据库名、用户名和强密码；
- `ARK_API_KEY`、模型名及现有集成所需服务端配置；
- Caddy 共享用户名和密码哈希；
- Next.js 服务端 API 地址。

生产环境文件必须被 Git 忽略。部署说明不得要求用户截图、粘贴或上传真实密码、私钥及 API Key。

## 部署与更新流程

首次部署：

1. 将已确认版本的代码传到服务器。
2. 在服务器创建生产环境文件并生成共享密码哈希。
3. 构建镜像，启动数据库，执行迁移，再启动其余服务。
4. 从 tunnel 日志读取随机 HTTPS 地址。
5. 用未认证请求、正确密码、API 健康检查和一条页面流程完成验收。

后续更新重新拉取代码并构建应用容器。只要 `tunnel` 容器未被重建，临时地址通常保持不变；如果地址变化，从日志获取新地址并重新通知测试者。

## 故障处理与数据保护

- 所有服务设置合理的重启策略和健康检查；依赖服务健康后再启动上层服务。
- PostgreSQL 使用持久化卷，重建应用容器不会删除业务数据。
- 任何会删除数据库卷的操作都不写入日常部署命令。
- 2 GB 内存下限制应用并发和构建并行度；已有 Swap 用于缓解短时峰值，但不替代内存升级。
- 通过 `docker compose ps`、各服务最近日志及健康接口定位启动问题。

## 验证标准

- 生产前端能够完成构建并以 production 模式运行。
- 公网不直接开放 `3000`、`8000` 和 `5432`。
- 无密码访问临时网址时收到认证挑战；正确密码可以进入页面。
- 页面可以通过同源 `/api` 读取服务状态和业务数据。
- API、worker 和数据库健康，数据库迁移完成。
- 重建应用容器后数据库数据仍在。
- 仓库与镜像中不存在真实密码、私钥或 API Key。

## 后续升级

测试通过后，购买并实名域名，把 Quick Tunnel 替换成固定域名入口。再根据实际使用人数决定是否升级到 4 GB 内存、托管数据库以及独立账号与权限系统。
