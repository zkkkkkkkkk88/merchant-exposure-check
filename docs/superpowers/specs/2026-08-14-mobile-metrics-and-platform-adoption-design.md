# 手机实测指标与平台资料采用设计

## 目标

在不扩大手机实测人工成本的前提下，让三题结果更容易理解；同时把平台查缺发现的公开资料转化为可被商家画像直接采用的结构化事实，减少重复录入和错误缺失提示。

## 范围

### 1. 手机实测指标

- 提及率、首批推荐率、场景覆盖率和信息准确率继续显示百分比。
- 每项同时显示分子与本轮已确认题数，例如 `1/3`。
- 增加独立结论卡：`本轮至少首批推荐一次`，值为“是”或“否”。
- 没有有效结果时不伪造分母，显示空状态；历史轮次仍以各自实际确认题数计算。

### 2. 平台查缺证据

每个平台结果展示：

- 本次搜索词；
- 命中的公开商家名称；
- 来源网址；
- 检索完成时间；
- 平台发现的结构化字段；
- 与当前商家画像的字段差异。

“未检索到”“检索失败”“待人工核实”保持不同状态，不把接口失败解释为商家未发布。

### 3. 采用到商家画像

- 仅对平台已发现且与当前画像不同的字段显示“采用到商家画像”。
- 支持字段：正式名称、地址、电话、营业时间、服务项目、资质。
- 点击采用前显示当前值、拟采用值和来源平台。
- 采用后写入商家画像事实并保存来源网址，不直接修改外部平台。
- 不自动覆盖商家已确认事实；若字段已有已确认值，必须由用户明确提交采用。
- 名称匹配不确定、没有来源网址或结果处于冲突状态时禁用采用，并提示先人工核实。

## 数据流

1. 平台 worker 保存搜索词、命中名称、来源网址、检索时间和发现字段。
2. 平台查缺接口同时返回当前商家画像值和可采用字段列表。
3. 前端展示字段级差异，用户提交一个字段的采用请求。
4. API 校验平台结果属于当前商家、字段允许采用、证据可追溯。
5. API 写入或更新画像事实，标记为已确认，并记录来源。
6. 页面重新读取画像和平台查缺结果，已采用字段不再提示缺失。

## 错误处理

- 任务仍在执行时不显示采用按钮。
- 来源缺失、匹配不确定或冲突时返回明确的 409/422 错误，不写入画像。
- 采用失败时保留当前页面和原资料，并显示字段级错误。
- 重复采用相同值保持幂等，不生成重复事实。

## 测试

- 前端组件测试：百分比与 `分子/分母`、至少一次首批推荐结论、平台证据和采用按钮状态。
- API 服务测试：允许采用、拒绝冲突结果、拒绝无来源结果、重复采用幂等。
- 路由测试：采用后画像返回新值及来源，平台结果不再报告该字段缺失。
- 回归测试：O'eat 等非医疗商家只使用通用字段，不出现医疗专属文案。

## 非目标

- 不自动登录或修改高德、百度、腾讯、抖音、视频号等外部账号。
- 不自动覆盖商家已确认资料。
- 不承诺采用资料后豆包一定推荐，只用于提高公开信息一致性和可核验性。
