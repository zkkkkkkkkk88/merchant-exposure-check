# 同类参照与推荐率行动方案

## 目标

让商家从总览中快速知道当前差距，并能进入独立页面查看完整同类证据；把“优先行动”从概括性结论改成能直接执行、验收并复测的任务，最终用于提高商家在相关联网回答中的推荐率。

## 方案选择

采用“总览摘要 + 两个独立详情页”的方案。相比继续在总览展开全部信息，该方案减少首页信息拥挤；相比弹窗，独立页面更适合承载大量问题、推荐依据和操作步骤，并能复制链接和返回。

## 页面结构

### 总览

- “同类参照”只展示前三个核心参照：商家名、覆盖问题数、适用场景、来源状态。
- 提供“查看全部同类参照”入口，保留当前商家参数。
- “优先行动”展示前三项摘要：标题、优先级、证据数和第一步。
- 提供“查看完整行动方案”入口，保留当前商家参数。

### 同类参照页 `/competitors?merchant=<id>`

- 按核心参照、候选参照分组。
- 每个商家展示：被哪些问题提及、回答为何推荐它、适用场景、已识别来源数量。
- 长回答依据默认折叠，用户按商家展开，避免页面成为长文本墙。
- 数据只来自该商家最新一次真实检测，不生成模拟竞争商家。

### 行动方案页 `/actions?merchant=<id>`

每项行动包含：

- 要解决的推荐缺口与证据问题。
- 具体步骤，按执行顺序编号。
- 建议渠道，例如官网、地图/团购平台门店页、公众号或权威行业页面。
- 需要准备的资料，例如地址、资质、服务项目、价格、医生信息、照片和更新时间。
- 可直接参考的公开表述示例，但不虚构事实。
- 完成标准，例如“至少两个公开页面采用一致表述并可被搜索访问”。
- 完成后操作：回到项目重新运行同一问题集进行复测。

## 行动生成规则

行动仍由真实检测缺口驱动，不调用模型凭空生成。每个问题分类映射到行业通用的执行模板；当前口腔医疗商家优先使用地域、精准品类、项目、价格、服务和场景模板。行动只能建议补充已确认或待商家核实的信息，不能建议制造评价、伪造资质或承诺排名。

推荐率提升的表述统一为：提高公开信息被检索、核验和引用的概率，从而增加进入相关回答的机会；不承诺平台排名或必然被推荐。

## 数据与接口

- 扩展 dashboard action：`description`、`steps`、`channels`、`materials`、`example`、`completionCriteria`、`questions`。
- 同类参照页可复用 dashboard 的真实 `competitors` 数据，暂不增加数据库表。
- 两个详情页均从 URL 中读取 merchant ID，所有导航继续携带该 ID。

## 异常与空状态

- 没有真实检测时，提示先完成检测，不展示模拟内容。
- 没有同类参照时，说明本次回答未形成可用参照，并提供返回检测记录入口。
- 没有行动时，说明当前问题集未发现明确覆盖缺口，建议扩大问题类型或再次检测。

## 验证

- 后端测试验证各问题分类生成完整行动字段。
- 前端测试验证总览只展示摘要、两个入口携带正确 merchant ID。
- 页面测试验证详情页只读取当前商家数据，商家切换后不回退到默认商家。
- 生产构建和真实浏览器流程验证：总览 → 同类参照 → 返回 → 行动方案。
