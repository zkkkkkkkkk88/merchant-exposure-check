# 交付报告、全局进度与移动导航设计

## 目标

让商家在一个页面看懂本轮豆包实测结果、主要缺口、下一步行动与复测变化；同时在全站明确当前位置和下一步，并保证窄屏设备可以访问所有核心模块。

## 交付报告

- 新增商家级“交付报告”页面，不依赖具体方舟检测记录。
- 汇总商家基本资料、手机三题与答案摘要、提及次数、首批推荐次数、是否至少首批推荐一次、重复竞品、来源差距、公开平台查缺、优先行动和同题复测变化。
- 每一部分无数据时显示明确空状态，不生成模拟结论。
- 提供“打印 / 另存为 PDF”按钮，调用浏览器打印能力；打印版隐藏导航、返回按钮和交互控件。
- 报告注明：结果来自用户确认的手机版豆包回答与公开页面，不代表平台官方排名或保证后续推荐。

## 全局六步进度

步骤固定为：商家画像、问题策略、平台查缺、手机实测、执行优化、同题复测。

- 商家画像：至少存在商家资料即进入已开始状态；有已确认画像事实时完成。
- 问题策略：最新题库存在至少 3 道已审核启用的推荐题时完成。
- 平台查缺：最近任务为 completed 或 partial 时完成。
- 手机实测：存在至少一轮 confirmed 手机实测时完成。
- 执行优化：存在手机实测行动方案时显示“可执行”，不虚构商家已完成外部发布。
- 同题复测：存在两轮可以比较的同题手机实测时完成。
- 进度条显示客观完成数量，并为每一步提供对应页面链接；“可执行”不计入已完成数量。

## 移动导航与可读性

- 小于 960px 时顶部提供菜单按钮，展开后显示全部主导航、当前商家和服务状态。
- 菜单使用真实按钮，支持 `aria-expanded`、键盘操作和当前页面标识。
- 打开页面或点击菜单项后菜单关闭。
- 正文辅助字号最低 12px；重要状态、表格说明和操作提示提高对比度。
- 移动端报告、指标卡、查缺差异和步骤条改为单列或双列，不产生页面级横向滚动。

## 数据与接口

- 新增 `GET /merchants/{merchant_id}/journey-progress`，返回六步状态、完成数和当前下一步。
- 交付报告复用现有商家、题库、平台查缺和手机实测接口，不复制业务计算逻辑。
- 不新增 PDF 库、外部账号登录或自动发布能力。

## 测试

- API：六步状态从空商家逐步变化；两轮同题实测完成复测步骤。
- 前端：全局进度的完成/可执行/待处理状态与链接。
- 报告：关键结论、空状态、竞品、平台差距、行动和免责声明。
- 移动导航：菜单可展开、包含全部模块、具有可访问属性。
- 打印样式：打印按钮存在，报告容器和 `@media print` 规则生效。
